# Portal Persona Pack 仕様 v1（ドラフト）

> **status: draft** — 現行実装（2026-08-10 時点）からの書き起こし。
> 実装が仕様を兼ねている状態を脱するための第一版。確定後は本文書が正、実装が従。

ペルソナパックは、AI 秘書アバターの**人格・表情・舞台演出をまとめたポータブルな配布単位**。
（設計の経緯は `docs/architecture/persona.md` を参照）。

> **2026-09-25〜 置き場を2つに分けた。** 人格（`card.json`）は個人に属するので非公開の vault
> （`vault/persona/card.json`。vault につき1つ）、見た目（`scene.json`・画像）は共通素材なのでアプリ側（`portal-app/assets/avatars/<slug>/`）。
> 以下の「パック」は、この2つを合わせた論理的な単位を指す。`card.json` の `defaultAvatar` が既定の見た目を指す。

## 1. パックの構成

```
vault/persona/                  ← 人格（非公開・vault につき1つ）
└── card.json          ← 人格の定義（必須）

portal-app/assets/avatars/<slug>/ ← 見た目（公開）
├── scene.json         ← 表情・背景・演出の定義（必須）
├── avatar.png         ← フォールバック立ち絵（必須）
├── image-prompts.md   ← 画像の生成用プロンプト（推奨・アプリは読まない）
└── expressions/       ← 表情差分画像（任意・後から1枚ずつ追加可）
    ├── neutral.png
    ├── happy.png
    └── ...
```

- 見た目ディレクトリ内のパス参照はすべて**そのディレクトリからの相対パス**。`basePath` のような絶対参照は書かない。これがポータビリティの根拠
- 表情差分が1枚も無くても動作する（`avatar.png` ＋ CSS 疑似表情で代用）。置いた表情だけ本物に切り替わる
- `image-prompts.md` は**画像の「ソースコード」**。表情を1枚だけ作り直す・9個目を足すには、同一キャラを再現できる元プロンプトが必須になるため、パックに同梱して持ち運ぶ。ランタイムは参照しない（「ランタイムが読むもの＝card/scene」「人間・生成ツールが読むもの＝image-prompts」の分離）。生成プロンプトの同梱は、オリジナル作品であることの裏付け（§7）にもなる

### パックに含まれないもの（境界）

| データ | 置き場 | 理由 |
|---|---|---|
| ユーザー像・関係の記憶（profile.md） | vault 側（`vault/persona-state/`） | 記憶はキャラではなく**ユーザーに紐づく**。人格を差し替えても記憶は残る |
| 会話ログ | vault 側 | 同上 |
| `avoidWords` の違反検知ロジック | アプリ本体（reply-feedback.js） | パックは**宣言**のみ持つ。強制はランタイムの責務 |

この境界（人格＝作者が書くもの・不変／記憶＝AIが書くもの・成長する）が本仕様の中核設計。

## 2. card.json — 人格の定義

```jsonc
{
  "spec": "portal-persona",   // 固定値（必須）
  "specVersion": 1,           // 本仕様のバージョン（必須）

  "id": "koharu",             // パック識別子。英小文字（必須）
  "language": "ja",           // ペルソナの言語（省略時 "ja"）。※v1 ではランタイム注入文は日本語のみ（§6-3）
  "name": "こはる",            // 表示名（必須）
  "userCallName": "あんた",    // ユーザーの呼び方。{呼称} の展開値（必須）
  "greeting": {               // 起動時の挨拶（文字列 または { "morning", "noon", "night" } オブジェクト / 必須）
    "morning": "おはよう！…",
    "noon": "こんにちは！…",
    "night": "おつかれさま！…"
  },
  "defaultAvatar": "koharu",  // 既定の見た目（assets/avatars/<slug>）。省略時は id と同じ slug。設定画面で上書きできる
  "voiceStyle": "",           // 任意。Gemini TTS の話し方の指示（例: "やわらかく、ゆっくり"）
  "avoidWords": ["どす"],      // この人格が使ってはいけない語（任意）

  "intro": "あなたは…",        // システムプロンプト冒頭（必須）
  "sections": [               // プロンプト本文。配列順がそのまま出力順（必須）
    { "heading": "キャラクター", "lines": ["…"] }
  ],

  "postHistory": []           // 会話履歴の後ろに置く指示（予約・現状未使用）
}
```

### プロンプトへの組み立て規則

1. `intro` を先頭に置く
2. `sections` を配列順に `【heading】\n lines...` として連結する
3. 全体の `{呼称}` を `userCallName` で置換する（未定義時は「ユーザー」）。`{userCallName}` も同義（非日本語ペルソナ向け表記）

### 設計原則

- card.json は**人間（作者）が書くもの**。対話で変化しない。変化する情報は vault 側へ
- `postHistory` は履歴後方に置く指示の予約フィールド。前方より強く効くため、破られやすい規律の移設先（Character Card V2 の `post_history_instructions` と同じ知見。実測の経緯は docs/architecture/conversation.md の変遷を参照）

## 3. scene.json — 表情・舞台の定義

```jsonc
{
  "spec": "portal-persona",         // card.json と同じ（必須）
  "specVersion": 1,                 // パック単位で1つのバージョンを名乗る（必須）
  "fallbackFile": "avatar.png",     // 表情差分が無いときの立ち絵
  "defaultExpression": "neutral",
  "defaultBackground": "mood",

  "expressions": [
    {
      "id": "happy",                      // タグ [表情:happy] で参照される
      "label": "笑顔",                     // UI 表示名
      "file": "expressions/happy.png",    // パック相対パス
      "aliases": ["嬉しい", "smile"],      // タグ解決時の別名
      "bg": "linear-gradient(...)",       // mood 背景時のグラデーション
      "glow": "rgba(...)",                // 立ち絵まわりの発光色
      "filter": "brightness(1.07)",       // 立ち絵への CSS filter
      "breath": "4.6s"                    // 呼吸アニメーションの周期
    }
  ],

  "backgrounds": [
    { "id": "mood", "label": "表情に合わせる", "mood": true },   // 表情の bg に追従
    { "id": "auto", "label": "時刻に合わせる", "auto": true },   // autoSchedule に従う
    { "id": "night", "label": "夜", "gradient": "linear-gradient(...)" }
  ],

  "inference": [                    // タグ無し応答の表情推定ルール（任意）
    {
      "expression": "sad",          // 一致したときの表情 id
      "patterns": ["ごめん", "残念"]  // 正規表現の配列。上のルールから順に照合
    }
  ],

  "autoSchedule": [                 // auto 背景の時刻→背景マッピング
    { "untilHour": 8, "background": "dawn" }
  ]
}
```

### inference — タグ無し応答の表情推定

AI 応答に表情タグが無いとき、文面の語彙から表情を推定する（無表情のまま固まらないための保険）。

- **推定語彙は人格の口調に依存する**（関西弁の「ええやん」等）ため、コードではなくパックが持つ
- 配列の順序＝照合の優先順位。悲しみ系を喜び系より先に置くのが定石（「嬉しいけどごめん」対策）
- `patterns` は正規表現として解釈される。1つでも一致したらその `expression` を採用
- 省略時・全ルール不一致時は `defaultExpression` に落ちる

### フォールバック挙動（必須要件）

- `expressions[].file` が解決できない表情は `fallbackFile` ＋ CSS 疑似表情（filter / transform）で代用する
- つまり**画像ゼロのパックも有効**。card.json ＋ scene.json ＋ avatar.png が最小構成

### 表情 id の標準セット

`neutral / happy / excited / gentle / thinking / worried / sad / surprised` の8種を標準とする。
標準セット準拠を推奨（AI への表情タグ案内・タグ無し時の推定が前提とするため）だが、
scene.json 上は自由に増減できる。

## 4. 画像要件

| 項目 | 要件 |
|---|---|
| 背景 | **透過必須**（アルファ付き PNG）。背景は scene.json の backgrounds レイヤーが描画 |
| サイズ | 長辺 1200px・数百 KB 以内（全表情を起動時に先読みするため） |
| 構図 | 縦長（3:4 程度）のバストアップ。円形フレームは入れない |
| 差分間の整合 | 全ファイルで構図・服・髪・顔の大きさ・位置を揃える（ズレると切替時に絵が跳ねる） |

## 5. ランタイムタグプロトコル

パックとは独立した、**AI 応答テキスト上のインライン制御タグ**の規約。
LLM プロバイダに依存しない（応答テキストを正規表現で解析するだけ）。

| タグ | 書式 | 効果 |
|---|---|---|
| 表情 | `[表情:id]`（別名: `expr` / `emotion`） | タグ以降の文章をその表情で表示 |
| 背景 | `[背景:id]`（別名: `bg` / `background`） | 背景を切り替え |
| 返信候補 | `[候補:短い返事A|短い返事B]`（別名: `返信候補` / `返信` / `reply` / `replies`） | ユーザー側に返信ボタンを提示（12文字以内・2つまで） |

- 区切りは `:` `：` どちらも可。タグ自体は画面に表示されない
- 1応答に表情タグを複数置け、話の流れに合わせた表情変化ができる
- id は `expressions[].id` → 一致しなければ `aliases` で解決
- **タグが無い応答**は文面の語彙から表情を推定する（精度より「無表情で固まらない」を優先）

## 6. 既知の課題と対応状況

実装から書き起こす過程で見つかった、仕様と実装のギャップ。

1. ~~**バージョン表記の不統一**~~ — **解消済み（2026-08-10）**。scene.json の独自採番 `version: 2` を廃止し、
   両ファイルとも `spec: "portal-persona"` / `specVersion: 1` に統一。パック単位で1つのバージョンを名乗る
2. ~~**タグ無し時の表情推定語彙がコードにハードコード**~~ — **解消済み（2026-08-10）**。
   scene.json の `inference` へ移管（§3）。こはるは関西弁語彙、こまるはひらがな語彙と、人格ごとに持てる
3. **ランタイム注入文（表情タグ案内・返信候補指示・ツール利用指針）が日本語のみ** — v1 の既知の制限として明記。
   card.json に `language` フィールドを予約済み（現状 `"ja"` のみ有効）。非日本語ペルソナ対応は
   注入文全体の多言語化が必要で、v2 スコープとする
4. ~~**`{呼称}` プレースホルダが日本語トークン**~~ — **解消済み（2026-08-10）**。`{userCallName}` を同義の
   別表記として受け付ける（§2）。`{呼称}` も引き続き有効
5. **LLM プロバイダ依存の確認結果** — card.json / scene.json / タグプロトコル自体は**プロバイダ非依存**であることを確認済み。
   Gemini 依存はランタイム（gemini.js の API 呼び出し・Function Calling 形式）に閉じている。
   将来の Claude / ローカル LLM 対応はパック仕様の変更なしで可能
6. ~~**表情画像の生成用プロンプトがパック外**~~ — **解消済み（2026-08-12）**。
   パック内の `image-prompts.md`（§1）として復元した。card.json への取り込み案（ペルソナ作成機能の検討時に浮上）は
   「card.json の全フィールド＝ランタイム契約」という明快さを守るため不採用とし、
   アプリが読まない別ファイル方式を採用。原本（vault/knowledge の2ファイル）は各パックへ移した

### パックの置き場と配布方式（設計判断）

パック自体は自己完結（相対パスのみ）だが、**人格は vault、見た目はアプリリポジトリ内**（`portal-app/assets/avatars/`）とする。
見た目は静的サイトの相対 fetch、人格は中間サーバー経由で読む。人格のインストール＝vault の `card.json` を置き換える、見た目のインストール＝ディレクトリを置き index.json に1行足す、という方式。
パックが自己完結している限り、将来「URL からパックを読む」ローダーを追加しても本仕様の変更は不要。

## 7. 配布ルール（プラットフォーム運用）

- 本体リポジトリに置くのは**本仕様書＋公式サンプルパックのみ**
- 第三者パックは各作者のリポジトリで配布し、本体はリンク集（awesome-list 形式）のみ持つ
- リンク集への掲載条件: **オリジナル作品、または権利処理済みであることの自己申告**。
  既存キャラクター（アニメ・VTuber・実在人物等）の無断ペルソナは掲載しない
- パックの著作権は作成者に帰属する
