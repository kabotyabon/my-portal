# 日記・タスク・チェックリスト

## いまの仕様

### 日記のファイル規約
- 当月は日別ファイル `vault/diary/YYYY-MM-DD.md`。先頭見出しは `# YYYY-MM-DD`。
- 過去月は暦年ディレクトリ配下の月次まとめ `vault/diary/YYYY/YYYY-MM.md`。見出しは `# YYYY年M月`、日ごとに `## YYYY年M月D日`、日と日の間は `---` 区切り。
- 雛形は `vault/diary/テンプレート.md`。年度（FY）ではなく暦年で切る。
- 一覧取得は `DiaryRepository.listEntries()` に集約。ルート直下の日別 → 年ディレクトリの月次の順に、必要件数に達するまでしかディレクトリを開かない（API節約）。移行前にルート直下へ残った `YYYY-MM.md` も後方互換で拾う。

### 日記の編集体験
- textarea ＋「プレビュー／編集」タブ切替。レンダリングは自作 `renderMarkdown()`（utils.js）。ライブラリは使わない。
- 入力のたびに localStorage の `diary-draft` キーへ自動保存し、再表示時に復元、保存成功時に破棄する（report.js）。
- プレビュー上のチェックボックスはクリックでトグルでき、未保存の変更として扱う。
- 「更新」ボタンで当日ファイルを手動再取得する（`fetchDailyReport()`）。取得は `cache: 'no-store'`——GitHub API は `max-age=60` を返すため、既定キャッシュのままだと書き込み直後の再取得が最大60秒古い内容を返していた（2026-08-19 修正）。
- AI チャットのツール（append_to_file / save_file）が今日の日記へ書き込むと `vault-file-written` イベント経由で自動再読込する（2026-08-19）。未保存のローカル編集（diary-draft）があるときは上書きせず、更新がある旨をメタ表示で知らせるだけに留める。それ以外のリモート変更（他端末での編集等）の自動検知はない。
- 「再生成」ボタンはブラウザ側の `DiaryService.generateTemplate()` で当日テンプレート（当日メモ）を生成して上書きする。これとは別に、vault リポジトリ側に手動起動の GitHub Actions（daily-report.yml）があり、テンプレート.md から当日ファイルを生成・再生成できる。生成経路は2本ある。

### セクション upsert と重複防止
- `upsertSectionInContent(content, title, body)`（report.js）: `## タイトル` から次の `## ` の前（または末尾）までを丸ごと置換し、無ければ末尾に追記する。AI振り返りが使う。
- `appendLineToSectionInContent()`: セクション末尾に1行足す蓄積用。感情ログが使う。
- `String.replace` は関数形式で渡し、本文中の `$&` 等が置換パターンとして解釈される事故を防いでいる。

### デイリーチェックリスト（2026-08-19 削除済み）
- 「今日の四つ」チェックリスト（`dailyTasks`・今日タブ・進捗バー・日記に反映）は 2026-08-19 に機能ごと削除した。関連の localStorage キー（`checklist_*` / `daily-task-*` / `daily-checklist-date`）は起動時に掃除される（config.js）。

### タスク
- `vault/task/tasks.json` が主ストレージ。キーは id / title / status（todo・doing・done・archived）/ priority（P1〜P3）/ labels / createdAt / updatedAt（＋任意で closedAt・dueDate・description）、ルートに lastSync。
- AIチャットのツール `get_tasks`（長期バックログ取得）/ `add_task` / `update_task` で操作する。
- 「今日のタスクは？」には `get_today_reminders` を使う。返すのは memo.md の未チェック行（`- [ ]`）のみで、tasks.json の P1〜P3 バックログは意図的に含めない（チェックリスト分は 2026-08-19 の機能削除で消えた）。

### メモ
- `vault/task/memo.md`。行頭 `## ` 単位でセクション分割し、1セクション＝1カードのアコーディオンUI（memo-tab.js）。最初の `## ` より前は「冒頭メモ」カード（改名・削除不可）。どのカードの保存からでも全カードをまとめて1コミットする。

### AI振り返り・感情ログ
- 振り返りボタンで日記本文・感情ログ・任意の一言メモを読み込み、ラベル分けしない3〜5文を生成して `## AI振り返り（YYYY-MM-DD）` へ確認なしで upsert 保存する。Kolb 4段階やルーブリック数値化はしない。
- 感情ログは「出来事＋感情タグ（固定語彙11種＋自由記述）＋強度1〜5」を `- HH:MM 出来事 → 感情（強度n/5）` の形式で `## 感情ログ（YYYY-MM-DD）` へ追記蓄積する。1日に何度でも記録できる。画像は対象外。

### 過去の記録パネル
- ルートは3つ: 日記（vault/diary）・ナレッジ（vault/knowledge）・記憶（vault/persona-state）。一覧 → クリックで開く → 編集 → 保存。編集の実体は汎用の `createFileEditor()`（file-editor.js）。
- 新規作成は一覧上部の追加行から、表示中のディレクトリへ作る。`.md` は自動補完。雛形はファイル名で決める: `YYYY-MM-DD` → `# YYYY-MM-DD`、`YYYY-MM` → `# YYYY年M月`、それ以外 → `# <ファイル名>`（日記の見出し規約に一致させる）。
- サブディレクトリ付き入力（`2026/2026-06`）は許可。絶対パス・`..`・`< > : " | ? *`・制御文字は弾く。同名ファイルは上書きせず開くだけ。作成直後は GitHub API の反映遅延を避けて、いま書き込んだ本文でエディタを開く（`openWith()`）。

### 月次まとめ
- AIツール `rollup_diary_month`（実体は `DiaryService.rollupMonth()`）で、指定月の日別ファイルを `vault/diary/YYYY/YYYY-MM.md` へ統合する。
- 当月は `force` なしでは畳めない。既に月次側へ見出しがある日はスキップする（冪等）。日別ファイルの削除は `delete_daily` を明示したときのみ、統合後の本文に各日の見出しがあることを確認してから行う。

## 既知の問題・残課題

- 日記のリモート変更の自動検知（Focus時のハッシュ比較・競合通知）は未実装。同一画面内の AI 書き込みは 2026-08-19 のイベント連動で自動反映されるようになったが、**他端末・別セッションでの変更**は依然、手動「更新」＋ドラフト保存で取りこぼしを抑えている。
- 過去の記録パネルに削除の口がない。誤って作ったファイルはリポジトリ側で消す必要がある。
- 新規作成時に未保存の編集があると `confirm()` で確認するが、破棄した内容は戻せない。
- 日記の生成経路が「ポータルの再生成ボタン（クライアント側生成）」と「GitHub Actions の daily-report.yml（テンプレート.md 起点）」の2本あり、生成内容が一致しない（前者はチェック済み項目＋当日メモ、後者はテンプレート本文）。
