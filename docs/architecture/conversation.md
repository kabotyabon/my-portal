# 対話UI・会話ログ・フィードバックループ

## いまの仕様

### 対話画面（VN方式）
- 立ち絵を全画面の地に敷いた Ambient Companion UI。台詞は句読点・60文字目安でページ分割し、42ms間隔の文字送りで1ページずつ表示する（送り中タップで全文、送り終わりタップで次ページ。`prefers-reduced-motion` では全文即時表示）。
- AI の返答末尾の `[候補:A|B]` タグから返信候補ボタンを常に2つ出す。タグが無ければ既定文言（挨拶直後は挨拶用の別セット）。タップはその文言をそのまま送信する。
- 表情は返答中の `[表情:happy]` タグをページ単位で反映する。タグ→アプリ状態（考え中=thinking・例外=worried）→文面からの推定、の3系統フォールバック。表情・背景・タグ仕様の詳細は persona.md を参照。
- 起動時の挨拶は AI 生成しない。card.json の `greeting`（未指定ならコード側の固定文）を表示する。「AI が話すのはユーザーが話しかけたときだけ」が原則。
- 「📝 日記に書く」ボタンは、入力欄に「日記に書いて」を入れて通常送信するだけの発話ショートカット（`requestDiaryWrite()`）。何を書くかは会話の文脈から AI が決めて `append_to_file` で追記し、何を書いたかを報告する。フォームからの直接書き込み方式は廃止した。
- 画面に出る文言に ADR 番号や実装用語を書かない（全 UI の規約）。

### エージェントループ
- バックエンドを持たず、ブラウザから Gemini を直接呼ぶ（`callGeminiRaw` + function calling）。`sendChat()` が最大5往復（`maxIter=5`）のループでツール呼び出しを処理し、テキストのみの応答が返ったら終了する。
- モデルは `gemini-3.5-flash-lite`（定義は gemini.js の `GEMINI_MODEL` 1箇所。settings.js の接続テストも参照する）。選定基準はコスト——実測の会話量（月360リクエスト前後）で月約¥190、予算上限（月¥1,000）に十分な余裕。上位が必要になれば `GEMINI_MODEL` の1行で変更する。思考トークンも `maxOutputTokens` の枠を消費するため、出力枠は 8192 とし、思考は `thinkingLevel: 'low'` で抑えて「思考だけで枠を使い切り parts の無い応答が返る」を防ぐ（旧 2.5-flash・枠2048・思考無制限の構成で、2026-08-17/18 に「日記に書いて」の空返答として実発生）。
- ループが返事なしで終わった場合（思考トークン切れ・ツール往復の上限到達・candidates 空）は `showChatFailure()` が「返事を作れませんでした」を台詞ボックスに表示し、失敗理由（finishReason 等）を `logChatFailure()` が会話ログへシステム行として残す。**ユーザー発話は履歴から消さない**——消すと直後の「も一回」が何の話か AI に分からなくなる（8/18 実発生）。例外時も同じ経路で失敗を見せ、記録する。
- 会話履歴は localStorage のセッション（直近30件）に保持する。端末間のチャット履歴同期はしない（記録は会話ログが担う）。

### 相談モード（`js/domains/counsel-mode.js`）
- 悩み・迷いを示す語彙（「悩」「相談」「しんどい」等の正規表現）にユーザー発話が一致すると自動的に入り、6往復を目安に自動で終わる。「ありがとう」等の短い締めの言葉でも即座に終了する
- 通常時の応答スタイル規律（1回3文以内・掘り下げは連続2回まで）をこの間だけ緩め、システムプロンプトに専用ブロックを追加する: 受け止める→事実と気持ちを分けて聞く→反転の問い・分解→小さな次の一歩、の順で深掘りを促す
- 判定はコード側（語彙の正規表現）で確定させ、AI には結果の指示だけを渡す。「相談っぽいかどうか」をAIの裁量に任せない
- 相談モード中の応答も含め、発話は通常どおり会話ログへ逐語で全文記録される（後述の「記録の書き込み方」とは対象が異なる。会話ログ＝全部・日記＝ユーザーの事実だけ、という役割分担）

### システムプロンプトの構成
送信のたびに次を組み立てる。

1. **人格・口調**: card.json 由来の人格定義（`getAiPrompt()`）。名前・口調・呼称・励ましの出し方はここにだけ書く
2. **現在日時**: `getJstNowContext()`（JSTの日付・曜日・時刻・昨日/明日）を毎送信時に評価して注入。「日付を推測しない」の絶対ルール付き
3. **応答スタイル規律**: 1回の返答は3文以内・共感や励ましは1文だけ・同じ入り方/締め方を続けない・情報を求められたらまず内容で答える・質問返しは連続2回まで・閉じの言葉の後は蒸し返さず短く締める
4. **記録の書き込み方**: 追記は `append_to_file`、`save_file` は全置換であることの警告。対象なしの「日記に書いて」は聞き返さず直前の話題を1〜3行にまとめて書く。
   **日記に書くのはユーザーが話した事実・気持ちだけ**とし、AI から見た評価・感想・分析（「〜な様子」「〜と感じられる」等）は書かない規律を明記している
5. **ツール実行の報告規律**: 実行していないことを「やった」と言わない・`ok: true` を確認してから報告・報告には「何を・どこに」を1行で・失敗時の謝罪は1文まで＋次の一手を添える
6. **返信候補タグ**: `[候補:A|B]` を必ず付ける（各12文字以内・ユーザーの口調で）
7. **promptGuide 群**: `AvatarScene.promptGuide()`（表情・背景タグ仕様）／`ReplyFeedback.promptGuide()`（反応の集計から導いた指示＋禁止語）／`PersonaState.promptGuide()`（ユーザーについて覚えたこと）
8. **その他**: `remember_about_user` の使用条件（明示的に頼まれたときだけ）、ツール選択指針（当日リマインドは `get_today_reminders` 優先）、ファイル保存先の規約
9. **現在のコンテキスト**（`AiService.getLatestContext()`、毎回・常時付加。チェックボックスでの選択式は廃止した）:
   直近の日記3件（各500文字）／アクティブなタスク／ナレッジ記事の索引（パス＋本文1行目。詳細は `read_file` で読ませる）／
   アプリの全体像（`docs/architecture/README.md` 抜粋）。ナレッジ索引とアプリ概要はセッション中1回だけ取得してキャッシュする
10. 添付ファイル（あれば）

### 原則: プロンプトに書いた規律は守られない——守らせたい制約はコードに置く
散文の指示・ツール説明文の注意書きは破られることが3回の実測で確認されている（報告規律・禁止語・「全文を渡す」のいずれも、書いてあったのに破られた）。対策は毎回「仕組み」に落とす。

- ツール戻り値を `{ ok, changed, ... }` に構造化し、失敗のエラー文に次の手を書く
- 書き込みの実効性を SHA 比較で検証する（空コミット＝追記漏れを `ok: false` で返す）
- 禁止語は card.json の `avoidWords` にアプリが照合し、違反したときだけ名指しの是正をプロンプト末尾に出す

プロンプトの責務分担の判断基準は「**人格を別のキャラクターに差し替えても成立する指示か**」。成立するならコード（画面制約・環境）、成立しないなら card.json（人格）。

### 会話ログ
- 1往復ごとに表示された全文を `vault/conversations/YYYY-MM-DD_アバター会話.md`（1日1ファイル・セッションごとに `##` 見出し）へ追記する。要約しない。記録主体はアプリ（`ConversationLog`）で、AI の自発的な保存には依存しない。
- ユーザー発話には評価種別（close/more/free/other、ボタン経由は「ボタン」）、AI 発話には採用された表情 id を `**[14:01] 話者（種別）:**` の書式で併記する。
- 書き込み失敗時は localStorage のキューに残し、次回送信時・起動時にフラッシュする。会話そのものは絶対に止めない。追記は読んだときの SHA で照合し、他端末と衝突したら読み直して最大3回組み立て直す。
- システムプロンプトに「この会話は自動記録済み。改めて保存不要」と明記し、AI の二重記録を防ぐ。

### フィードバックループ
- 評価UI（★・👍）は置かない。**すでに毎回押している返信候補ボタンの押され方**を評価とみなす: 閉じ系候補=close（満足or切り上げ）／掘り下げ系=more（説明不足）／候補を使わず自分で入力=free（候補が的外れ）／文脈候補を押した=other（機能している）。
- 永続先は vault の会話ログ1本。起動時に直近3日分を並列で読んで集計を復元する（localStorage の集計は廃止。セッション中の揮発分だけメモリに持つ）。読むのは GitHub API であって Gemini ではなく、プロンプトに載るのは集計から導いた結論の数行だけ（実測: 遡る日数を3→30日にしてもプロンプト長は不変）。
- 直近20件の窓で集計し、5件溜まるまでは傾向とみなさない。close≥50%→2文以内に、more≥35%→最初から具体を1つ、free≥40%→固有名詞を含む候補を、の定型指示を次のリクエストへ還流する。判定は JS 側で確定させ、生の数字は AI に渡さない。
- 集計とは別に、直近3回の返答の書き出し8文字を毎回渡して同じ入り方の反復を止める（件数が溜まる前から効く）。
- 禁止語は2段構え: 平時は「次の語は使わない」の1行、違反を検出したら名指しの強い是正に切り替える。宣言（何を禁じるか）は人格側、照合の仕組みはコード側。
- 学習状況（内訳とリセット）は設定画面に出す。根拠が見えないと挙動の変化が不気味になるため。

### 定期改善（会話ログを読んでプロンプトを直す）
自動で回るのは観測（集計→しきい値→数行の指示）まで。**所見を出してプロンプトを直すのは人がやる**。手順:

1. 前回改善以降の `vault/conversations/` を全部読み、発話そのものを根拠に所見を出す（評価種別で絞り込める）
2. 各所見を「人格を差し替えても成立するか」で振り分ける——コード規律（応答スタイル・報告規律・ツール仕様）はシステムプロンプトやツール実装へ、人格固有の癖（擦り切れた締めの言葉・感情への触れ方）は card.json へ
3. 効いたかどうかは次回の同じ手順で検証する（第1回で日時注入の効果、第2回で報告規律の効果を確認済み）

## 既知の問題・残課題

- **相談モード直後の日記書き込みで「事実だけ」規律が破られるリスクは未検証**。相談モードはAIに分析的・反転的な物言いを促す設計のため、直後に「日記に書いて」と言われるとその口調のまま書いてしまう可能性が通常会話時より高い（プロンプトに書いた規律は破られる、という本ページ既知の教訓の具体例になりうる）。次回の定期改善で相談モード後の日記書き込みだけ抜き出して確認する
- **プロンプト規律の効き目検証が次回の定期改善待ち**。特に「質問返しは連続2回まで」はコーチング的な人格の持ち味と拮抗するため、締めすぎていないかをログで見る
- **禁止語が実際に守られるかは未検証**。プロンプトに載ることは確認済みだが、従うかは対話で見るしかない。守られなければ「検出時に1回だけ言い換えを求める」が次の手（Gemini 呼び出しが増えるため効果を見てから）
- **AI がツールを「呼ばずに報告した」のか「呼んだが失敗した」のかをログから切り分けられない**。前者なら戻り値の改善では防げず、ツール呼び出しの有無をアプリ側で記録する必要がある
- **集計のしきい値（50/35/40%）と窓幅20件は初期値のまま**。実測に基づく調整をしていない
- **`avoidWords` は部分一致**で短い語は誤検出する。違反の記録はメモリのみで端末をまたがない
- **フラッシュに失敗した往復はリロードで集計から落ちる**（会話ログが唯一の保存先になったトレードオフ）
- **プロンプト組み立てが2箇所にある**。対話（ai-chat.js）と日記の AI 振り返り（report.js）が別々に組んでおり、責務4層の分担は対話側にしか適用されていない
